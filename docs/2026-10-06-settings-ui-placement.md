# Auto 与 Typesafe 设置入口

## 行为契约

本次调整管理界面入口和弹窗交互，沿用现有模型表格、浮窗、间距、颜色和层级。首页保持原来的主体网格；高级设置保留统一 Classifier 下拉框和同一行的“保存设置”“设置”按钮，不展示 Auto 或 Typesafe 的完整表单。

Auto 在“模型配置”的模型列表中独立固定在首行，标为“内置默认配置”，标识为 `auto`。该行只提供配置按钮，不能删除、测试或停用；它不是数据库模型记录，不进入上游模型数量、筛选或普通模型 CRUD。没有上游模型或筛选无匹配时该行仍存在，下方显示相应空态。模型分组继续保持现有行为。

点击 Auto 配置或 Typesafe 设置后打开居中的浮窗。浮窗沿用已有设计 token，限制高度，内容区滚动，底部保存和取消按钮固定。每次打开重新读取配置；取消不写入。ESC、遮罩及关闭按钮使用相同关闭逻辑，有未保存修改时确认放弃，保存期间禁止关闭和继续编辑。键盘焦点保持在当前弹窗，关闭后恢复到入口按钮，背景不能滚动或操作。

Auto 浮窗配置现有 `auto_routing_config`；“启用按任务选模”只改变路由策略，关闭后继续使用兼容默认路由，不删除或停用 Auto 固定入口。仅对 Kiro Auto 主生成请求生效，任务选模及连续工具回合规则不变。价格显示按实际选中的上游模型计算，不为 Auto 编造固定价格。

Typesafe 浮窗配置现有 `typesafe_classifier_config`，只处理 Kiro 独立 `chat / do / spec` classifier。高级设置使用统一 Classifier 下拉框选择 Typesafe 或原模型，选择 Typesafe 时显示配置中的 `jev` 模型；“保存设置”和“设置”在同一行。浮窗只配置参数，启用与停用由下拉选择保存决定，不再提供第二个开关。Key 的掩码保留、替换和清除契约不变；成功提交立即清理明文，再读取掩码，关闭后销毁表单。读取失败明确显示并禁止保存覆盖，提交成功但重新读取失败明确区分，不伪报提交失败。当前选择与事务契约见 [Classifier 统一模型选择](2026-10-06-classifier-selection.md)。

## 范围与验证

布局调整不改变后端选模、计费、接口格式或数据库结构；后续 Classifier 统一选择补充设置的批量写入事务，见统一选择契约。不创建 Auto 数据库记录，不部署或重启程序。现有未提交实现保留；修改前为相关文件和前端构建目录创建校验过的恢复副本。

使用本地 HTTP Mock 和无界面浏览器验证首页入口、Auto 固定行、零模型和筛选空态、弹窗开关、键盘焦点、尺寸、背景锁定、未保存确认、保存期间锁定、保存键隔离、Key 掩码及错误行为，不截取屏幕。完成前端构建，构建未部署桌面候选，交由未参与写入的只读代理独立复审。
