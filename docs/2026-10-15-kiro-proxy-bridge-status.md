# Kiro 代理模式、桥接安装与启动状态

## 目标与现场证据

用户已运行修复 `getSession` 接口的新 dev，但安装目录仍保留旧桥接。当前代理是 `capture`，一键配置按既有契约关闭桥接并跳过安装；界面只依据 `http.proxy` 显示“已接管”，因此不能解释为什么新修复尚未应用。模式切换只改变 Go 代理，不会更新已运行的 Kiro 启动环境。

官方会话另有三次 `run_workflow` 参数校验失败：同时提供 `workflowPath` 与 `workflowPrompt`。随后仅提供 `workflowPath: bundled://investigate` 及 `inputs.brief/report_path` 的调用创建、调度成功。该调用不能验证 Auto 加 `agent://` 的桥接修复；后续工具中断也不能当作相同接口错误。

前端通用请求超时为 30 秒，首次完整预检已有超过 30 秒的实测记录。超时不取消后端安装流程，不能让页面报错后自动再次提交。

## 可观察行为

1. Kiro 配置卡只显示一次“已配置/未配置”状态；模式和代理地址各占一行。抓包与转发的请求去向由操作模式和日志页呈现，不在卡片中加入常驻说明。代理模式即时改变 Go 侧行为，不能据此宣称已经更新运行中的 Kiro 环境。
2. 卡片默认不显示桥接文件的版本、校验结果、加载推断或完整重启理由。需要重启时仅显示“需重启 Kiro”；安装诊断异常时显示一条简短提醒，原始诊断仍保留在状态接口。文件识别或启动命令提交不能当作运行中的 Kiro 已加载。
3. 抓包且代理已配置时提供“转发并重启 Kiro”按钮。点击后先切换模式，再调用现有重启入口完成预检、旧版迁移、安装和启动。重启失败时保留实际已切换的模式并显示原始错误，不自动回滚或重复提交。
4. 转发且桥接需要更新时提供“更新并重启 Kiro”。已配置不再隐藏应用新桥接的入口。
5. 日志页切换模式后持续显示 Kiro 桥接需要通过重启同步的说明，并提供明确的重启操作。模式切换本身不自动结束正在执行的工作流。
6. 配置、还原和重启的客户端等待预算为 180 秒；普通请求仍为 30 秒。等待期间禁用重复操作，返回 `ok:false` 时按失败显示，并刷新真实状态。

## 状态接口契约

`GET /api/kiro-proxy` 保留现有字段，增加 `proxy_mode` 和 `stage_bridge`。

`stage_bridge` 包含：

- `required`：当前代理归属、模式和有效 Auto 配置是否要求启用桥接。
- `reason`：不启用原因，例如 `capture`、`proxy_unconfigured`、`routing_disabled`。
- `installation`：`verified_current`、`record_current`、`record_previous`、`original`、`legacy_previous`、`unknown`、`error` 或 `unsupported`。
- `message`：对应安装识别结果的中文说明。
- `adapter_sha256`、`expected_adapter_sha256`、`bundle_sha256`：识别记录及当前文件身份，不进入上游请求。
- `verified`：仅当前验证器的可信缓存或已完成的安装预检能够证明完整文件对应当前候选；自洽恢复记录不构成此证明。
- `restart_required`、`restart_reason`：根据安装识别和本代理最近提交的启动计划给出应用提示。
- `last_launch`：可空的最近启动计划摘要，包括 `submitted_at`、`proxy_mode`、`bridge_enabled`、`bundle_sha256`、`adapter_sha256`。它表示本代理提交过的启动条件，不表示当前进程环境已核实；代理重启或 Kiro 被外部启动后不能据此承诺实际加载。

安装诊断只读取文件、计算摘要、验证恢复记录或查询已有可信缓存，不调用 JavaScript AST 解析、候选编译、安装或缓存写入。身份未知时保持未知；真正安装仍沿用完整预检、旧候选重编及字节比较、退出确认、备份和原子替换。

旧静态清单中的 `candidate_sha256` 与 `previous_versions` 均属于迁移来源，统一识别为 `legacy_previous`。它们不能证明当前结构 adapter 身份，不设置 `verified` 或伪填当前 `adapter_sha256`。只有自洽的当前结构记录命中按目标路径、完整文件摘要、adapter 及本验证器绑定的可信收据，才显示 `verified_current`。

模式接口保留 `mode`，增加 `kiro_restart_required`、`kiro_restart_reason` 供切换页面提示。最近启动摘要仅在本代理成功提交启动后更新，失败不能留下成功状态。

## 验证与边界

后端使用临时文件、Mock 启动器和测试缓存，覆盖新旧记录、可信收据、未知或损坏文件、抓包与转发、启动失败、模式切换、缺省最近启动记录及并发读取。前端使用本地 HTTP Mock 验证状态呈现、模式切换后重启的顺序、失败不误报成功、状态刷新和生命周期请求的超时预算；阻止真实外部请求。

本轮只修改当前工作区并编译新的 `desktop,dev` 调试产物，不切换 Git 分支，不改变真实 Kiro 配置、数据库或安装文件，不自动重启当前应用。工作流互斥参数保持官方校验，不自动删除其中一个参数或改写失败结果。未确认工具声明缺陷前不改桥接 profiles 或重新生成大型规则文件。
