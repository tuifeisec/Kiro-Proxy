# Kiro 手动切换模型后的 Agent 选模

## 问题与证据

Kiro 聊天模型下拉框切换的是当前父会话的模型。代理已经按每条入站请求的 `modelId` 路由；但 Kiro 工作流步骤原生优先使用节点和工作流定义的模型，注册子 Agent 也可能经过 inline、类别模型或 `subAgentStartCategory`。旧桥接仅处理 Auto 继承，因此手动选择具体模型后，新步骤或子 Agent 仍可能使用先前配置的模型。近期日志同时出现多个会话和模型，不能仅按时间相邻推断父子关系；此修复以已核实的创建调用链为依据。

## 行为契约

在桥接生效且聊天下拉框手动选择具体模型时，之后新启动的工作流步骤和普通注册子 Agent 统一使用**当前父执行的模型 ID**。工作流节点模型、Agent 定义的初始模型、inline 模型、类别模型和类别路由不覆盖这次手动选择。聊天模型由 A 切换到 B 后，新启动的步骤和子 Agent 使用 B；已经运行的执行继续使用原模型，不在工具续轮中途改模型。

聊天下拉框选择 `Auto` 时，工作流步骤继续使用用户配置的节点模型，普通注册子 Agent 继续使用现有 Auto 职责选模规则。桥接未启用时保留 Kiro 原生选模行为。代理仍按实际入站 `modelId` 路由，不根据时间或会话名猜测模型。工作流创建时保存父会话模型；已创建并运行的工作流不会因聊天下拉框后来切换而重写其快照。

## 验收

对 legacy 和 native 两类真实 Kiro bundle 的当前桥接生成及迁移做 Mock 回放。覆盖父模型 A → B 后新工作流步骤和子 Agent 使用 B、Auto 工作流保留节点选模与子 Agent 职责选模、桥接未启用时保留原生节点/inline/类别路由，以及安装升级的旧候选逐字节校验。真实 Kiro 安装与运行中的扩展加载另行验证。
