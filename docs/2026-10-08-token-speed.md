# 请求输出速度与仪表盘平均速度

## 行为契约

用户要求请求统计逐条显示 tok/s，仪表盘用量明细按模型显示平均 tok/s。费用继续使用 USD，Kiro IDE 的 Credits、计价和 Auto 路由保持原有语义。本次在当前 main 分支实施，并分别以中文说明提交费用修复和速度统计，推送到 origin。

### 单请求输出速度

沿用现有 SSE 内容观测器，额外保存末次内容到达时间 `last_content_ms`，与 `first_content_ms` 同样相对请求开始计时。可识别内容包括文本、推理和工具输出；协议元数据、仅用量或终止事件不作为内容。观测器不提前读取、不改变返回内容或事件分类。

`tokens_per_second = output_tokens × 1000 / (last_content_ms - first_content_ms)`。

这表示代理观测到的输出速度，受网络传输、事件分片和上游输出 Token 统计口径影响，不是模型内部的精确生成速度。输出 Token 沿用现有用量记录，包含该协议计入输出的推理或工具 Token，不把输入、缓存 Token 加入分子。

只有请求成功、输出 Token 大于零、首内容已观测且观测完整、首内容时间非负、末内容时间晚于首内容且不晚于总耗时，才有有效速度。旧记录、非流式响应、失败请求或未完整观测内容区间的中断请求、观测不完整、仅一个可识别内容事件或首末时间区间为零的响应不套用总耗时估算；API 返回 `null`，界面显示 `—`。字段不在展示前舍入，界面显示两位小数。成功与完整性沿用既有记录语义；上游内容和终态均已完整观测、下游随后取消的请求，若原路径仍记为成功，完整测速区间仍可参与统计。

请求列表增加“输出 tok/s”列，详情展示同一值、内容时间区间和计算说明。新增列保持横向滚动，不压缩现有费用与耗时字段。

### 仪表盘平均速度

按日期、模型长期保存有效请求的 `generation_speed_sum` 与 `generation_speed_samples`。平均 tok/s 是有效单请求速率的算术平均：先累加完整精度速度及样本数，合并日期或模型后再相除，不平均已舍入的数字，也不平均每日均值。

请求记录和速度日汇总在同一事务内保存，避免记录写入失败却产生测速样本；模型身份沿用现有 Kiro 可见的统计模型名，模型身份为空的请求不加入按模型速度汇总。日汇总的速度累加不再增加请求数、Token 或费用，这些继续通过原 Stats 路径记录。原统计刷盘只能累加其负责的字段，保留已存速度汇总。只有速度样本、尚无其他统计的行也参与返回。清空统计及其失败重试都在单一事务中删除请求记录和日汇总，避免双表清空之间插入孤立速度数据。

API 的按日模型行返回上述两个汇总字段；仪表盘用量明细每个模型增加“平均 tok/s”及样本数，并显示当前范围全部有效样本的平均值。没有有效样本显示 `—`。当天、日期范围和全部历史均使用同一长期汇总；请求明细七天保留期不会删掉速度日汇总，清空用量统计则一并清空。

测速样本以请求记录的落库自然日归属。原 Token 和请求计数仍通过独立的 Stats 路径记录，午夜或清空时的在途请求可能落在不同统计边界；本次不将所有请求指标宣称为同一事务原子结算。

旧数据库新增字段默认零；旧请求没有末内容时间，不伪造速度或回填估算。速度样本从运行本版本之后开始累计。原历史 Token、金额、请求数继续展示，因此旧历史的请求数可以大于测速样本数。
