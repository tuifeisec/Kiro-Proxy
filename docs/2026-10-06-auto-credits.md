# Auto 路由与本地估算积分

## 行为契约

本次修复采用用户确认的口径：配置价格计算出的费用以美元计，除以 `0.04 USD/Credit` 后得到本地估算积分。这不是 Kiro 官方账单，也不能据此预测官方 Auto 的实际扣款。

```text
普通输入 = max(输入 Token - 缓存读取 Token - 缓存写入 Token, 0)
费用 USD = (普通输入 × 输入单价 + 输出 Token × 输出单价
          + 缓存读取 Token × 缓存读取单价
          + 缓存写入 Token × 缓存写入单价) / 1,000,000 × rate_multiplier
本地估算 Credits = 费用 USD / 0.04
```

单价单位统一为 `USD / 百万 Token`；`rate_multiplier` 是本地费用倍率，默认 1。它与官方模型列表的倍率不构成可互换的定价表。现有 Provider 默认价格是本地预填值，用户应按实际渠道价格填写。费用拆分字段 `input_cost`、`output_cost`、`cache_read_cost`、`cache_write_cost` 保持 USD；`credits` 字段统一改为本地估算积分。

流式 `meteringEvent.usage`、请求明细和汇总使用同一计算结果，不在传输或持久化前按三位或六位小数截断。按用户确认，管理界面的 Credits 统一四舍五入显示两位小数（如 `3.52`、`0.00`），仅在展示时格式化，避免逐帧舍入导致累计偏差；USD 费用分项继续显示六位小数。Kiro 用量限制响应的 `currentUsage` 保留整数，`currentUsageWithPrecision` 保留小数。该响应统计当前本地自然月的代理用量，并返回下月月初作为重置时间。它不包含抓包模式中官方账号的扣款；清空代理统计也会清空这项本地累计。

旧数据库在启动迁移中一次性将 `daily_stats.credits`、`request_usage.credits` 和 `settings.stat_credits` 由旧费用数值转换为新积分数值（乘 25）。保留迁移前数据在专用备份表，转换与版本标记在同一事务内完成，重复启动不重复换算；金额拆分、Token 和模型配置不改。升级后不能直接运行旧版程序继续记账，否则会混用单位；回滚应恢复升级前数据库备份。本次开发验证仅使用临时测试数据库，不修改正在运行的数据库或切换正在运行的代理模式。旧文本日志不重写，其中升级前代理自算的 `credits` 仍采用旧费用单位；抓包得到的官方计量值始终按官方积分理解。

## Auto 按任务选模与兼容默认路由

2026-10-06 复核后，用户已选择按明确任务字段与能力规则选模，已增加独立策略配置、实际模型锁及选模日志。启用时显示 `Auto（按任务选模）`，不需要同名 Auto 分组；官方说明、首版规则、配置和验证见 [Auto 官方说明与任务路由复核](2026-10-06-auto-task-routing.md)。以下旧兼容行为仅用于策略未启用时，便于核对；它不能代替按任务选模。

转发模式将 `auto` 作为显式的 Kiro 虚拟模型标识。未启用任务策略时，模型列表提供 `Auto（默认路由）`。

1. 优先使用名称为 `Auto`（大小写不敏感）的启用分组；同名启用模型可作为单模型目标。
2. 没有 Auto 专用配置时，选择模型列表里的默认项：首个具有可用候选的启用分组；没有可用分组时选择首个启用模型。
3. 分组内复用现有优先级、健康检查、并发容量、图片能力过滤和故障转移规则。没有可用目标时不伪造成功，也不把 Auto 指向彩蛋模型。
4. 保留 `requested_model=auto`，`model_id`、`selected_model_config_id` 和积分使用最终实际候选。classifier 跟随主模型时使用相同的 Auto 解析。
5. 本地 OpenAI/Anthropic 兼容入口的未知模型仍保持原有精确匹配约束，不引入任意模型兜底。

设置名为 `Auto` 的分组只能控制旧默认候选和失败接管，不能让代理判断不同任务应使用哪个模型。新增任务策略通过明确角色与字段映射选择实际模型，并按主会话/独立分支保留已选配置；具体错误处理与缓存边界以任务路由文档为准。

## 官方资料与结论边界

- [Kiro 模型选择](https://kiro.dev/docs/chat/model-selection/)：Auto 按任务路由；模型倍率、推理深度和 Token 数都会影响用量。
- [Kiro 定价](https://kiro.dev/pricing/)：额外积分价格为 `0.04 USD/Credit`，界面按小数积分计量，账户用量至少每五分钟更新。Auto 结合前沿和专用模型、意图识别与缓存等机制。
- [Kiro Billing](https://kiro.dev/docs/billing/)：用量按请求分数计量，按账期重置。

上述页面没有公开完整的 Auto 底层模型选择轨迹或可从第三方 API 用量精确复算官方积分的公式。`费用 / 0.04` 是本项目经用户确认的本地估算定义。
