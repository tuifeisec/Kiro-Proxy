# Kiro 阶段桥接预检性能优化

## 目标与现状

用户要求保留普通 Kiro 更新后的自动适配能力，并将重复配置、重启前的预检缩短到秒级。完整文件 SHA256、必要结构、变量绑定、自动模型域、安装前并发检查和完整备份继续生效，不增加功能开关。

本轮开始时工作树只有旧版精确哈希清单安装器，正在运行的程序则为自动兼容候选。该候选程序 SHA256 为 `7e257950eace26bdbb71813c50eff40ff26cf03aa13c277ada7be74064a78302`；其内嵌结构规则为 `1890969` 字节，SHA256 为 `3cfca7cb7f4808d82bb54141b203ab4900852afc86b1f808ac43e6a38259445d`。恢复时必须核对这两个摘要，不能使用先前未通过复审的规则代替。可见解析器源码备份早于环境原语和 ASI 修复，恢复后须重新验证这些契约。

结构规则的原始字节同时参与已安装桥接记录的身份校验，因此 `.gitattributes` 禁止对该 JSON 转换换行；恢复测试固定核对其字节数、摘要及两个结构族的 hook 数量，避免 Windows `core.autocrlf=true` 检出时改变适配器身份。

本机原版 bundle 为 `14501392` 字节。只读基准中，读取约 4–5 ms，SHA256 约 8 ms，独立 Node 进程的 V8 基础编译约 221–249 ms。该基准不执行扩展，也不等同于完整 AST、绑定和注入校验；不能用它证明新实现已达标。

## 可见行为

首次遇到新原版时，解析并验证结构及作用域，生成候选，复验候选语法、注入声明、捕获引用和环境原语来源。关键结构变化、歧义、ASI 行为变化或绑定变化继续明确失败，在预检失败时不停止 Kiro、不改代理设置、不改真实 bundle。

成功验证后保存代理自己建立的验证凭据，以完整目标内容 SHA256、适配器摘要及验证器版本为键。重复预检必须读取真实文件并计算完整摘要；命中有效凭据时复用已验证结果，不恢复原版和重跑编译器。只依据 bundle 尾部记录及其自洽摘要不足以建立可信缓存。

Windows 持久凭据使用当前用户 DPAPI 加密并校验完整性，绑定目标绝对路径、适配器摘要及当前代理可执行文件完整摘要；程序摘要在进程内只计算一次，任何验证代码或依赖变化自动失效。DPAPI 不提供应用身份认证；同一 Windows 用户下可任意调用 DPAPI 的进程不在该凭据的隔离边界内。该凭据用于防止仅改写 bundle 或自洽尾记录绕过完整验证，以及发现凭据的偶然损坏。不新增依赖或用户设置。缺少凭据表示尚未缓存，走完整验证；损坏、无法解密及 I/O 错误保留原始错误并明确返回，不以错误伪装缓存命中。并发目标变化仍由安装前摘要复核拒绝。其他平台保持原有 Windows 桥接不受支持的边界。

预检只读取凭据。只有完整验证完成并且安装或幂等核验成功后，才保存凭据并发布内存条目。凭据以完整键的摘要命名，使用唯一临时文件、同步写入和不覆盖已有目标的原子发布；同键并发写入只接受内容相同的已存在凭据。保存失败须明确报告桥接已经核验或安装的实际状态及备份路径，不回滚已验证的 bundle，也不发布内存命中。

## 性能改动

1. 结构规则只解码一次，保持不可变；一次建立 token key 索引，以稀有固定 token 定位候选，继续完整验证上下文、AST 形状、绑定双射及全局唯一性。
2. 有序编辑区间与 token 单向归并，替代每个编辑对全部 token 的扫描。
3. 复用可安全复用的分析中间结果，减少重复解码、作用域查找及大数组分配。不得仅为提速删除必要的候选绑定校验。
4. 重复预检复用已验证结果；Kiro 内容、适配器或验证器变化使缓存失效。SHA256 用于完整性与身份，不作为新原版兼容白名单。
5. 停止旧 Kiro 后立即检查是否退出，仅在仍运行时每 100 ms 再检查，最多使用原有 2 s 等待预算；已退出时立即继续。查询失败或期限内仍运行时继续阻止安装和启动，并保留停止命令的原始错误。

## 验收与交付边界

Mock 覆盖正常命中、内容/路径/版本变化、缓存损坏、读写失败、伪造自洽尾记录、失败不缓存、预检后变化及输入不变。真实新旧原版以只读输入进入临时测试目录，覆盖生成、重命名、ASI 拒绝、环境原语捕获拒绝、安装备份及幂等。按需回放实际 SDK/raw 方法，不执行完整扩展。

分别记录首次原版适配、首次识别已安装桥接、进程内重复命中和持久凭据命中的耗时与分配。重复预检以低于 200 ms 为目标，首次适配以 1 s 为优化目标；未达到时记录实测与剩余热点，不以缓存结果冒充首次分析结果。IDE 本身的窗口和扩展初始化时间单独计算。

本轮仅修改当前工作树、运行相关测试并生成候选。不切换分支或工作树，不替换当前运行程序，不改写真实 Kiro 安装，不登记正式授权指纹、不部署、不推送。最终候选须经独立复审，明确实际耗时和未解决问题。

## 本轮验证结果

2026-10-14 在 Windows x64、Go 1.26.4 上使用真实 bundle 的只读副本验证；安装目标和 DPAPI 凭据均在测试临时目录。下表是预检耗时，不包含 IDE 窗口、扩展初始化和完整配置接口处理。

| 场景 | 首次完整预检 | 进程内缓存预检 | 新缓存实例读取 DPAPI 凭据 |
| --- | --- | --- | --- |
| 14,501,392 字节的原版首次适配 | 23.124 s | 12.056 ms | 11.943 ms |
| 14,572,633 字节的已安装桥接、尚无凭据 | 24.887 s | 34.724 ms | 15.722 ms |

后一次测量与行为回放同时运行，表中保留原始结果。缓存路径的 compiler 调用次数保持为 1，证明没有重复解析。完整安装、备份和凭据写入为 95.560 ms；已安装文件幂等核验及凭据写入为 61.075 ms。另有独立测试通过真实子进程读取 DPAPI 凭据，验证其跨进程可用；表中的持久耗时通过同进程的新缓存实例测量，不能把它称为代理进程完整启动耗时。

重复预检达到低于 200 ms 的目标；首次完整适配没有达到 1 s，当前仍需约 23–25 s。文件、适配器、验证器程序或缓存身份变化后会重新完整验证，首次使用本候选识别已有桥接也有该开销。未测量旧程序的完整基线，不报告未经测量的首次加速倍数。旧失败诊断的 CPU profile 只覆盖一次 12.87 s 的不匹配运行，不作为最终完整预检的性能归因数据；依赖解析器内部仍有线性作用域查找，后续首次适配提速需要另行处理该解析热点。

恢复与验收证据：

- 从旧最终候选提取原始 profiles 和 1.3.0 manifest；解析器及结构实现从可见备份恢复并补齐 AST Shape、ASI、环境引用与绑定来源检查。函数调用的 `OpPrec` 字段保持在 Shape 中；`Reference` 区分固定属性名与可绑定标识符。native 重新生成候选的完整 SHA256 为 `05893583b44233eaaa1eaaafd82b39bbc1f6c0d07f2e0c90c0293e0942fee8fe`，与现用桥接逐字节一致。

- 真实 native 的缺失 hook、语法错误、部分安装、错误绑定、重复 hook、路径帮助函数语义变化和模块来源变化共 7 种输入全部拒绝，输入摘要保持不变。
- `test/kiro_stage_auto_behavior_test.mjs` 从当前产物提取实际辅助函数、SDK/raw 调用、子代理及 session services 方法进行 Mock 回放；8 个变体全部通过，原生 Auto/手动模型与 fallback 边界通过。旧回放夹具已补入从当前候选提取的环境别名声明，未执行完整扩展。
- 12 个登记 globals 分别经真实 parser 覆盖无遮挡允许、同名参数/`var`/`let` 遮蔽拒绝，共 48 个分支；另有 Math 参数捕获、固定属性名、ASI/换行注释、绑定双射和唯一匹配回归。
- 缓存身份失效、损坏/解密/读写错误、自洽伪造尾记录、预检后目标变化、写凭据失败保留安装状态及跨进程 DPAPI 测试通过。Windows 同键并发写入暴露的 sharing violation 通过共享删除权限的读取句柄修复，保留 `os.PathError` 与原始系统错误；30 轮并发回归通过。

最终由新的独立 Astra/high 只读复审者完成验收，无代码交付 blocker；独立重跑局部回归和 native-alpha 的实际 SDK/raw、子代理、职责与原生路由回放通过，并核对 8 个当前产物的记录及还原摘要、候选构建身份和 Git 字节一致性。放行范围仅为重复预检提速候选，不含首次秒开、整机 IDE 启动性能或部署验收。

## 2026-10-15 解析器升级复测

现场 12:02:16 至 12:03:05 的预检耗时约 49.7 秒。用当时旧桥接文件的只读备份（SHA256 `05893583b44233eaaa1eaaafd82b39bbc1f6c0d07f2e0c90c0293e0942fee8fe`）作为 `KIRO_STAGE_PERFORMANCE_BUNDLE`，测试只在临时目录安装候选。升级前首次预检为 49.488 秒；成功路径 CPU profile 中，依赖解析器 `js.Scope.findDeclared` 累计 24.46 秒。`github.com/tdewolff/parse/v2` 从 `v2.8.16` 升至 `v2.8.17`；该版本增加作用域变量索引，来源为上游 tag `7d52e93ca1f3eeb01555f0522ed656b239fe0c1a`。

在提交 `96fff02` 的阶段规则上，仅升级解析器后的同输入首次预检为 20.609 秒，候选 SHA256 仍为 `cd630132d9224d3d4c82af9f3b9f2ca3e870f620c21331268887088ce69ec48a`；测试目录内安装和凭据写入为 94 毫秒，内存及持久凭据命中为 11–12 毫秒。另以原版备份和当时已安装桥接文件复测首次预检，分别为 10.858 秒和 11.303 秒，候选摘要均不变。`go mod verify`、解析器语法/作用域/注入绑定/错误拒绝的 13 个相关测试通过；独立只读复审没有发现本次依赖升级的阻断问题。

这些测量只说明对应源码和样本的改进，不代表 Kiro 窗口就绪时间，也不覆盖随后并行开发中的新 adapter 规则。首次完整预检仍非秒级；当目标文件、adapter 或代理程序摘要改变时，原有可信凭据会失效并重新验证。未启动或替换正在运行的代理，也未重启真实 Kiro。
