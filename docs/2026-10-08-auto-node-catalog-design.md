# Auto 节点目录与快捷配置契约

## 目标与边界

用户保留现有 18/20 职责，希望日志中发现的额外节点有可核对的用途、清楚的配置入口，并能一次为多个节点添加或更新目标。本次改动仅整理观察与日志证据、改善 Auto 设置草稿，不改变 v2 配置、选模优先级、工作流桥接或执行快照。

在当前 main 工作区实施，不创建分支或工作树。不得运行测试、Mock、应用、界面、模型请求或实际 API，不写真实配置/数据库，不安装、部署、停止或重启。仅执行静态检查、前端构建与根目录 desktop/dev 编译；交付新文件名，不覆盖正在运行的 dev 程序。用户后续明确授权修复完成后提交并推送 GitHub，提交说明使用中文；仅提交本次源码和文档，不包含运行日志、真实配置、二进制或无关文件。

## 节点显示与配置范围

1. 完整且合法的 `definition_id + definition_revision + node_path` 是独立规则的身份。相同身份只显示一张节点卡，目标、职责、渠道、等级等路由变体收进历史。不同定义或修订即使同名也不合并。
2. 当前进程观察和历史日志分别计数，不能相加冒充实际调用总数，因为它们可能覆盖同一请求。卡片显示最近观察、两个来源计数和可展开的路由记录。
3. 无完整身份但带当前布局内的 `selected_duty` 时，提供“配置该职责目标”入口，只修改既有职责目标，明确影响该职责全部请求，不伪造独立节点规则。
4. 无身份且无可配置职责时，提供“配置默认目标”入口，明确影响全部未匹配请求。按可核对的工作流、会话、阶段、Agent 与任务上下文展示，不把裸节点名或 Agent 名当作规则身份。
5. 完整身份的卡片只需选择已有职责、单模型或模型分组，再点添加/更新；支持批量。独立目标复制目标的默认思考等级，职责绑定沿用职责当前目标与等级。高级编辑仍可单独改等级。
6. 已有独立规则不再禁用快捷操作。选择独立目标明确更新原规则；选择沿用职责时明确提示将删除同身份独立覆盖并改为职责绑定。批量先校验全部候选及最终草稿，全部有效才赋值；不得部分成功。
7. 搜索节点名、真实工作流标题、用途和身份；过滤“待配置、已有规则、未归类、缺身份”，默认优先展示可配置且尚未添加规则的节点。提供显式“选择当前筛选结果中的可配置节点”和“清空选择”，按完整身份去重，不自动预选。筛选隐藏的已选项仍计入总数并在批量预览提示，全部选中项统一校验。配置只改草稿，外层保存后生效；运行中的执行实例仍沿用快照。

现有职责目标表默认收起，保留全部编辑能力，让节点目录无需越过 18/20 行表单才能使用。“配置该职责目标”入口先展开目标表，再定位对应行；折叠只是界面状态，不新增路由开关或配置字段。

快捷校验允许保留原有无关草稿错误，但不能引入新错误。新增错误的比较按稳定节点身份、目标与错误类别进行，不能使用包含数组下标的展示文字作为错误身份；删除独立覆盖或更新顺序不得让其他未改变的错误变成“新增”。默认排序先显示有完整身份且待配置的节点，随后显示缺身份上下文和已有规则。

职责布局切换的待确认节点选择也按完整稳定身份暂存、校验和显示，不能以数组下标记住选择。单项或批量快捷更新、删除或新增绑定后，选择仍属于原身份；新身份必须单独确认。仅在应用切换的同一次同步操作中，按当前绑定顺序将身份选择转换为现有 helper 的索引参数，保留 helper 接口契约。工作流标题的来源显示使用 `activity_source_*`，路由行与原始请求节选分别使用各自来源字段。

## 真实日志信息

新增只读 `/api/auto-routing/history`，在 proxy 注册并复用流量日志权限。只读取配置的流量日志与 `.1`，不扫描工作流目录，不写回进程内观察。未取得权限、接口失败、读取不全和非法日志等均显示明确状态，不能把失败当作“没有节点”。

解析 `auto-routing.metadata` 的原始身份和路由字段，以及 `interceptor.detail` 二次 JSON 内的 `payload` 活动。工作流标题只在同一 session、精确 workflowId、精确 nodeId 对应时附到路由记录；存在歧义或缺关联字段时不附，不从 activity 的 nodePath 补造规则身份。记录日志文件名与行号以便核对。

历史接口另返回 `activity_nodes`：按 session、workflowId、nodeId 精确去重的活动节点、活动条数、标题及来源，并标明是否有精确对应的 Auto 路由。界面将没有对应 Auto 路由的活动单独列为“活动线索”，支持按名称和标题检索，不与 Auto 路由次数混算。活动线索没有稳定定义身份，不提供伪造的独立绑定，也不声称它没有模型调用或走了默认目标；只显示用途参考和“尚无同会话 Auto 路由证据”的原因，后续取得完整 Auto 身份才能快捷配置。

活动中的 user 文本仅截取有明确 `original_user_request` 标记的原始请求，至多 280 个字符，放在展开详情，标为“关联会话原始请求节选，非节点职责定义”。只显示普通文本，不执行、不解析为 HTML，不用于职责推断或路由。未知节点至少显示真实工作流标题、节点名、可用职责/阶段上下文及说明来源；没有证据时诚实标为用途待确认。静态名称说明仍作参考，不声称掌握所有未来工作流定义。

节选状态区分可用、缺少关联/原始标记、同键文本歧义和因可识别凭据样式未显示；状态附中文解释，不将显示过滤或证据歧义伪装成“没有任务”。可识别样式检查不证明任意文本已完成全面敏感信息审查。

历史读取使用可注入 `io.Reader` 的纯解析边界。每个文件按开始读取时的大小取快照，最多读取末尾 128 MiB，超出时报告截断并舍弃首个不完整行。每行上限 16 MiB；最多保留 1024 个路由变体和 2048 个关联上下文，超限报告覆盖范围。保留读取/解析错误及行号，用户取消请求时终止读取。接口不返回完整正文、headers、工具入参或凭据。

活动关联字段超过解析边界时也须提示字段名和限制、标记关联覆盖不全，不能只增加活动总数却无声丢掉目录线索。缺少可选关联字段仍表示无法关联，不伪造值。节选来源展示严格使用接口的 `excerpt_source_*` 字段。

进程内观察增加已有的工作流版本、阶段、来源、提供状态、workflowId、Agent、conversationId 和 executionId 元数据，仅用于解释与关联。`task_type` 显示为“请求携带的职责参考”，其显式声明、内置映射或继承来源在现有协议中不可区分，不能标成“客户端明确声明”。
