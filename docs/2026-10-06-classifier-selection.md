# Classifier 统一模型选择

## 用户可见行为

高级设置只保留一个 `Classifier 模型` 下拉框，包含跟随主模型、不使用 Classifier、`Typesafe classifier · <配置模型>` 和已有上游模型。Typesafe 默认模型为 `jev-1.13.0`；修改弹窗内的模型参数后，下拉标签同步显示新的配置模型。单次执行记录仍以 Typesafe 响应返回的实际模型为准。

“保存设置”和“设置”按钮在同一行。前者提交当前分类模型选择，后者在选择 Typesafe 时打开参数弹窗，其他选项时不可用。Typesafe 弹窗配置 API Key、模型、地址、超时、价格和代理，不再提供第二个启用开关；弹窗保存不切换分类执行方式。选择尚未保存时明确标注待保存和当前生效项，避免将编辑中的选项当成已生效配置。

页面读取时，以后端实际配置确定下拉框选项：Typesafe 已启用就显示 Typesafe，未启用就显示原 `classifier_model_id`。模型列表读取失败或缺少该 ID 时，保留显示已配置 ID 并标注“列表中不可用”，不将选择静默显示为空或改成默认值；模型列表恢复后显示正常名称。选择 Typesafe 后点击“保存设置”才启用它，保留原模型 ID；选择其他选项后保存，关闭 Typesafe 并记录新选项。前端专用值 `__typesafe__` 不写入 `classifier_model_id`，也不创建普通模型记录。未配置 Key 时启用失败，保留原错误并允许进入设置补全配置。

弹窗关闭或参数保存后的重读保留尚未提交的下拉选择；成功保存主选择后，重新读取并显示实际生效项。读取失败禁止继续保存覆盖；提交已成功但重读失败明确提示“已保存，重新读取失败”，不能伪报失败或继续显示旧项已经确认生效。提交失败后重读当前状态，保留用户未提交的选择与原始错误。
