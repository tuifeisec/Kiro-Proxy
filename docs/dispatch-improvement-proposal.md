# 模型分组与自动切换 —— 我的需求

## 我要解决什么问题

我现在用 kiro-proxy 转发请求到上游 API。每个模型配一个 key，如果这个 key 限额了、封了、余额用完了，整个模型就废了。我必须自己去前端手动改配置，换一个 key 才能继续用。

我不想每次都手动换。我希望提前把"能互相替代的模型"放一组，前面那个挂了，系统自动试下一个，我不用管。

---

## 我具体要什么

### 1. 我自己分组

我要能在前端创建一个组（比如叫"GPT-4o 主力组"），然后从已有模型里挑几个放进去。

我放进一组的模型，不要求 name 相同，不要求 provider 相同，不要求 base_url 相同。比如：

```
我的组："GPT-4o 主力组"
  ├─ GPT-4o 官方（openai, api.openai.com, sk-aaa）
  ├─ GPT-4o 中转A（openai, relay-a.example.com, sk-bbb）
  └─ GPT-4o Azure（openai, xxx.openai.azure.com, key-ccc）
```

这三个 name 不一样、地址不一样、key 不一样，但我觉得它们能互相替代，所以我把它们放一组。这是我的决定，系统不要替我猜。

### 2. 组内顺序我定

我要能排优先级。谁排第一，请求就先试谁。第一个不行再试第二个。

```
优先级 0：官方（最快、最稳，优先用）
优先级 1：中转A（官方挂了用这个）
优先级 2：Azure（最后的备选）
```

### 3. 切换是自动的

请求来了，走优先级 0。如果优先级 0 返回 429（限额）、401（key 废了）、超时、连接失败——自动跳到优先级 1，不用我操心。

我不要看到报错之后自己去改配置。

### 4. 不分组就不变

我有些模型不需要备用，就不放进任何组。它们的行为和现在完全一样——一个模型一条记录，该怎么转发怎么转发。我不希望因为加了分组功能，把现有的东西搞复杂。

---

## 为了让自动切换靠谱，我还需要的辅助能力

### 错误分类

不是所有失败都应该"试下一个"：

| 情况 | 我期望的行为 |
|------|-------------|
| 429（限额） | 换下一个模型试 |
| 401/403（key 无效） | 换下一个模型试 |
| 502/503/504（上游挂了） | 换下一个模型试 |
| 连接超时 / DNS 失败 | 可能是我本地网络问题，试一个就够了，别全部试一遍 |
| 上游返回 400（请求本身有问题） | 不要换，换也没用，直接报错给我 |

### 简易熔断

如果某个模型连续失败了好几次，短期内别再试它了。我不想每次请求都浪费 3 秒去试一个已经挂了的 key。

比如：连续失败 3 次 → 60 秒内跳过它 → 60 秒后放一个请求试探 → 成功了就恢复。

这个不需要持久化，重启后重置就行。

### 时间兜底

如果一个请求已经等了 9 分钟才失败，不要再重试了。剩的时间不够再试一次有意义的请求，直接告诉我失败了。我不要等 19 分钟。

---

## 我不需要什么

| 能力 | 为什么不需要 |
|------|-------------|
| 按 IP 回避某个 key | 我就一个人用，没有多 IP 的问题 |
| 并发控制 / 排队 | 我不存在几十个请求同时抢一个 key 的场景 |
| 回复质量评分 | 我不需要系统判断"这个回答够不够好" |
| 自动升级模型 | 我不要系统替我决定"这个模型不行换更贵的" |
| 客户端画像 | 我的入口就 Kiro + 本地兼容两种，不需要识别 20 种客户端 |
| Fallback 路由组（系统预设） | 我自己分组就够了，不需要系统再搞一套"主组/备组"的层级 |
| 分布式状态 | 单进程，内存里记一下就行 |

---

## 前端我要看到什么

1. 模型管理页面能创建组、给组起名
2. 能把已有模型加进组、从组里移除
3. 能拖拽或上下调整组内优先级
4. 组内模型在列表里能看出来属于哪个组、排第几
5. 不属于任何组的模型照常显示，不受影响

---

## 数据库怎么存（我的理解）

`models` 表加两个字段就行：

- `group_id`：属于哪个组（空 = 不属于任何组）
- `group_priority`：组内排第几（数字越小越优先）

不需要新建表。组名之类的元信息存 settings 或者后续再说。

---

## 总结

我要的就是：**我分好组、排好序，然后系统帮我自动切换。挂了不用我管，没挂不打扰我。**
