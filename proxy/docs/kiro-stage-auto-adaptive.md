# 阶段桥接工具维护说明

代理的 raw Auto 路由不再依赖 Kiro JavaScript 阶段桥接。Kiro 启动时显式设置 `KIRO_PROXY_STAGE_BRIDGE=0`，不读取 `extension.js`、不运行结构预检，也不安装或恢复补丁。CA 注入、代理模式和进程启动校验仍按原启动流程执行。

仓库保留结构适配器、manifest、安装和恢复工具，用于兼容既有文件的诊断、维护与回归测试；运行时匹配必须要求一个结构族的全部 hooks 唯一匹配，并保留跨 hook 变量绑定校验。任何 hook 缺失、重复或结构歧义都必须拒绝候选。不得以部分匹配、hook 数量或优先级猜测客户端结构。

存量合法代理头仍可由拦截器兼容解析，但新启动链不会生成该头。日常启动和状态查询不安装、不删除、不修改用户实际 Kiro 文件；用户需要恢复存量文件时，应通过明确的恢复流程处理。

activity 路由的数据契约、状态时序和无桥接行为以[activity 驱动 Auto 路由契约](../../docs/2026-10-20-activity-driven-auto-routing.md)为准。
